## 에이전트가 셸로 한 rm, mv 는 되돌릴 수 없다

- 발견: [확인 필요]
- 원인: Claude Code 문서에 체크포인트는 Bash 명령으로 바꾼 파일을 추적하지 않는다고 적혀 있다. git 은 커밋한 파일만 다룬다.
- 해결: 옮기기와 휴지통 MCP 도구, 조작마다 누가 왜 했는지 남기는 저널. 셸 `rm`, `mv` 는 훅이 막고 도구를 쓰라고 안내한다.
- 검증: 실제 Claude Code 세션을 헤드리스로 돌려 녹화했다(2f9fa80).
- 결과: 파일 199개를 정리한 뒤 `wasnew undo` 로 199개가 전부 제자리로 돌아왔다.
- 남은 것: 훅 없이 셸로 지우면 기록되지 않는다. `watch` 스냅샷이 안전망이다.
- 커밋: d0c8cf2, 9458655, 2f9fa80

## 대량 조작이 느리다

- 발견: [확인 필요]
- 원인: 조작마다 잠금과 저널 쓰기를 한 번씩 했다.
- 해결: 256개 단위 group commit. 이동은 이름 바꾸기로 한다.
- 검증: `scripts/bench-git.mjs` 로 같은 일을 git 과 비교, 3회 중앙값.
- 결과: 256 MB × 8 정리 11 ms, git 은 11,458 ms. 되돌리기 12 ms, git 은 8,667 ms.
- 남은 것: 바뀌지 않은 작은 파일 5,000개 다시 스냅샷은 git 보다 느리다(151 ms 대 57 ms). 첫 스냅샷 저장 크기는 원본과 거의 같다(2,048 MB). 같은 내용은 한 번만 두지만 압축은 하지 않는다.
- 커밋: 1cc6eb8

## 옮긴 뒤 다른 세션의 에이전트가 옛 경로를 찾다 실패한다

- 발견: [확인 필요]
- 원인: 에이전트는 파일이 옮겨진 걸 모른다.

- 검증: 테스트, 데모의 invoice_oct.pdf 장면.
- 결과: 옛 경로 읽기를 막고 새 경로를 알려 준다.
- 남은 것: [확인 필요]
- 커밋: d83f86e

- 원인: 이전 보유자가 잠금 파일을 지우는 중에 열면 EPERM 이 난다. 두 스냅샷이 statcache.json 을 동시에 바꾸면 rename 이 EPERM 으로 실패한다.

- 검증: CI 를 ubuntu, windows, macos 와 Node 20, 22 로 돌린다.
- 결과: [확인 필요]
- 남은 것: [확인 필요]
- 커밋: b7bbc82, a3252f9

## 남은 문제

- 바뀌지 않은 작은 파일 5,000개 다시 스냅샷은 git 보다 느리다(151 ms 대 57 ms). wasnew 는 Node 에서 파일마다 stat 하고, git 은 Windows 에서 캐시한 디렉터리 스캔을 쓴다. 원인까지 README 에 적어 두었다.
- 첫 스냅샷 저장 크기는 원본과 거의 같다(2,048 MB). 같은 내용은 한 번만 두지만 압축은 하지 않는다.
- 신뢰 정책은 편의 기능이지 보안 경계가 아니다. 클라이언트 이름은 아무거나 보낼 수 있다(README 에 적음).
- 에이전트가 훅 없이 셸로 지우면 기록되지 않는다. `watch` 스냅샷이 안전망이다.
- npm 에 아직 올리지 않았고 외부 사용자는 없다.
